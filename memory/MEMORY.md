# HomeBuild Log Memory

## 一句话

HomeBuild Log 是本地优先的装修工作台：主题聚合长期事项，账本、待办与问题、调研笔记、踩坑记录是日常操作入口，支持直接记录和持续处理；统一录入退为“随手记与整理”辅助工具，时间线与统计供回顾查看。

## 稳定事实

- 产品用户：单一业主本人，个人私用。
- 长期用途（用户2026-10-16明确）：持续记录清晰的卡片，为日后的过程总结和可视化展示积累素材、保留更多呈现可能；具体可视化形式尚未确定，不据此提前锁定展示方案或新增功能。
- 技术基线：React、TypeScript、Vite、FastAPI、SQLite、本地附件目录。
- 部署入口：`ubuntu26` 的 Docker 服务使用家庭有线局域网；最近确认的地址、镜像、数据库版本和验收状态统一见 `memory/CURRENT.md`。
- 数据目录：项目根目录 `.local-data/`，不得进入 Git。
- 来源录入：文字必填，可附加单个图片或 PDF 作为证据；当前不对附件做 OCR 或视觉理解。
- 附件查看：记录详情通过登录鉴权读取原件，可查看或下载；令牌只放请求头，前端临时 blob URL 在收起/卸载时释放。
- AI：默认关闭；来源整理支持本地规则兜底；近期回顾只读汇总当前正式记录及过程，手动选择日期与主题，引用实际记录，无业务自动写入。MiMo 和 DeepSeek 可作为 OpenAI 兼容供应商。
- AI 提取连接异常复用备用供应商和本地规则；候选不再要求或展示连续原文摘录，保留来源关联与人工确认；旧摘录数据不清除。踩坑分析绑定请求代次，内容变化后的旧响应不回填；AI 后续能力见 `AI_FOLLOWUP.md`。
- 语音：随手记、业务长文本、调研快速新增、账目／待办标题、公共记录／候选标题、主题名称及尺寸方法／口径复用 `VoiceInput`／`VoiceField`，单会话互斥，追加到最新草稿；单行转写合并换行并以空格追加，多行按换行追加。录音／转写与待修正结果按实例汇总阻止表单保存；退出／切字段取消并忽略迟到结果。超长结果保留人工修正；MiMo 转写沿用既有配置，无备用转写服务，失败就近报错。
- 语音静音防护：`frontend/src/voiceAudio.ts` 与 `backend/app/api/transcriptions.py` 使用一致的PCM能量门控；静音不上传／不调用模型，无可识别文字要求重录并保留草稿。该检测不等同人声识别，真实设备校准状态见CURRENT。语音视觉统一归 `frontend/src/VoiceInput.css`，独立底部工具行避开文字滚动区，并就近承载普通完成／失败／重试反馈，文本域统一取消原生缩放手柄。响应式可见性由 `useMediaQuery.ts` 订阅断点驱动，隐藏取消会话；转写结束只恢复仍归本次工具的焦点。调研可收起字段的超长待修正转写随事项草稿保留。
- 正式记录：事件、账目、问题、尺寸、决策、调研。
- 新建正式记录必须选择至少一个空间及一个装修阶段，不自动推测归属；直接录入、调研新建、候选确认与尺寸复测统一约束。原始来源仍可先保存，历史记录编辑／追加及已确认候选重复确认保留缺归属兼容。前端 `RecordAssociations.tsx` 在新建、编辑中均常显空间与阶段，`requireContext` 只控制必填语义，创建入口单独校验；服务端只在 `api/domain.py::_create_record_in_session` 校验创建，不能放进共享更新校验或候选解析适配器。
- 账本与待办业务页通过 `/api/v1/records/direct` 直接创建；来源快照、正式记录与审计原子保存，继续复用既有校验和统计。调研与踩坑沿用各自持续追加流程；当前部署状态以 CURRENT 为准。
- 来源展示：`frontend/src/sourcePresentation.ts` 严格识别直接录入的生成快照，搜索、列表与选择器等入口只显示创建时标题和说明，待办无说明时回退事项内容；详情按下一条规则展示。数据库与接口完整原文不改。生成快照的原文编辑入口只读，业务修改走正式记录；普通来源仍可编辑。候选原文摘录已停用，来源快照仍保留。
- 记录详情以当前记录为准：账目 `description` 明确显示为“备注”，编辑沿用“备注（可选）”；详情不再跳转“打开原始来源”，生成快照正文不重复展示，无附件／待复核时隐藏该卡片。普通来源原文、附件和来源变更复核仍就地保留；搜索与整理工作台继续支持原来源处理，后台快照、关系与审计保留。
- 尺寸：使用可增减的命名尺寸项，保留原顺序、重复测点及未知方向；输入支持毫米、厘米、米，保存统一毫米，切换单位保持实际尺寸。近似值、误差口径、方法及测量时间单独保存。“再次测量”创建关联的新记录，清空旧数值与来源，不覆盖旧事实、不自动采用最新值；复测历史通过相关记录查看。
- 账目：只记录付款、退款、收入；金额统一人民币，净支出为付款减退款再减收入。
- 待办与问题：待办、普通问题和施工问题仍复用 `issue` 类型，显示名称为“待办与问题”，状态为待处理、处理中、已完成。
- 待办可选截止日期 `due_date`；无日期不推测。逾期为未完成且截止日期早于北京时间今天，未来7天包含今天至第六天，已完成不计入。
- 正式记录使用整数版本；编辑和替换关联须携带读取版本，服务端同事务原子校验，409返回最新记录。前端保留草稿逐项对照，不自动覆盖；追加进展、来源及关系变化也维护版本。前后端需配套升级，旧客户端缺少版本拒绝保存。
- 全局搜索涵盖正式记录与其调研追加／待办进展、主题和踩坑处理记录，过程按父记录去重并提供定位摘要。业务筛选仅作用于正式记录，其他组仅按关键词匹配；各组共同分页。
- 主题：独立聚合层通过 `record_topics` 与 `pitfall_topics` 连接原内容，支持多主题且不复制记录；进行中／已归档，归档不联动子事项状态，保留归属可编辑、解除，新增归属须先恢复。概览为手写目标与现状、服务端未完成待办与最近10条活动，下方完整时间线每页30条。AI 暂不自动指定主题或更新旧事项。
- 待办历史：`issue_activities` 原子保存创建起点、状态变化及独立进展备注，同状态不重复登记；完成与重新打开保留完成信息快照，旧事项升级前历史不回填。调研与踩坑过程继承父事项主题归属，界面原“调研主题”改称“调研事项”。
- 调研笔记：独立入口复用 `research` 正式记录，快速创建保留原始来源；只保留主题与追加式调研过程、来源和待确认事项。状态为待调研、调研中、已归档，恢复到调研中后才可继续追加；服务端拒绝归档事项追加，并用版本CAS防止并发归档写入。详情以调研过程为主，追加表单默认收起、保留草稿；事项信息在过程下方折叠，先查看再编辑。结论功能停用，旧字段及历史表保留读取兼容，写入接口禁止结论更新；旧 `concluded` 在读取、筛选及统计中按 `comparing`（调研中）处理，不批量改写真实数据。
- 正式记录创建与通用编辑入口将主题归属常显；调研详情改在“事项信息”中按需编辑；“更多信息与关联”默认折叠，支持背景字段、多人和可搜索的具体记录关联。同主题记录优先但可选全项目，主题改变不清除直接关联、不自动填充背景；调研父事项通过专项接口同事务保存。
- 公共下拉：单选、多选、来源选择与来源操作共用 `useDropdown` 的互斥、外部关闭、Escape及无滚动焦点恢复，使用 `DropdownChevron` 表达展开状态；定位复用 `useDropdownPosition`，Portal菜单只滚动自身，不使用活动选项的祖先 `scrollIntoView`。
- 核心原则：原始事实优先、人在回路、一事多记录、视图不是副本、不确定性显式化、本地与隐私优先。

## 默认读取

新任务默认只读取：

```text
AGENTS.md
memory/MEMORY.md
memory/CURRENT.md
```

然后根据任务类型按需读取：

- UI、页面、组件、视觉：`PRODUCT.md`、`DESIGN.md`；按需使用 `.agents/skills/impeccable/SKILL.md`，接入与更新见 `docs/impeccable.md`。Windows 命令统一走 `scripts/impeccable.cmd`。
- 按钮视觉：`frontend/src/styles/buttons.css` 为公共操作按钮与分段控件材质入口，变量在 `frontend/src/styles/tokens.css`；主蓝／辅助浅蓝／危险浅红，禁用保留各自色系、不使用灰白填充，高对比模式尊重系统色。`primary-button`／`secondary-button`／`danger-button` 表达用途，语音超长结果的应用／放弃也接入；裸按钮兜底仅放 legacy 层，不覆盖独立组件。相关记录为整行可点击列表，布局在 `ui-hardening.css`；内容卡片、选择器、菜单选项、导航、图表图标和语音工具保持独立。
- 图表筛选：`EChart.tsx`、`ChartControls.tsx`／`chart-controls.css` 管理标题右侧纯图标分类与清除，不常显操作说明或已选项文字。传入 `selectedKey` 表示筛选模式，同项再点取消；未传时保留账本等明细动作。`hasActiveFilter`／`onClear` 支持无单一数据点的手动日期范围；空结果须保留清除入口。高亮由 `chartConfig.ts` 的 `withChartSelection` 作用于当前服务端数据，不补造完整分布。
- 阅读页筛选折叠：`FilterDisclosure.tsx`／`filter-disclosure.css`；时间线、记录分析、搜索默认收起条件，分析类型标签和搜索关键词常显。面板隐藏不卸载，收起关闭Portal并恢复焦点，保持页面原有查询时机；页面接入在 `CoreViews.tsx`、`AnalyticsViews.tsx`。

- 重要操作、部署、迁移或长期决策的历史事实：`memory/LOG.md`。
- 数据库迁移：`backend/migrations/README.md`，再读当前 head 或目标迁移。
- 主题与待办历史实现：`backend/app/topic_models.py`、`backend/app/topic_service.py`、`backend/app/api/topics.py`；主题迁移为 `0021_add_topics_and_issue_activities`，截止日期与版本迁移为 `0022_add_due_date_and_record_version`。前端入口为 `frontend/src/TopicsView.tsx`，公共选择为 `TopicSelect.tsx`。

## 检索规则

- 项目级 Hook 会定向注入命中的 PITFALLS/LOG 片段，并在每轮结束前触发一次记忆审计续行；它不自动写记忆，也不保存完整工具日志。
- 文档负责记方向、边界和长期事实；代码搜索负责确认实际影响范围。
- 任务涉及多个代码入口时，必须搜索调用方、类型定义、测试和样式，不能只靠文档判断。
- 不要默认读取历史任务、旧路线图、旧检查清单或全量迁移。
- 信息不足时追加新的 `Need:`，说明下一步需要读取什么。

## 记忆职责

- `MEMORY.md`：稳定事实与检索路由，不记录动态部署版本和测试计数。
- `CURRENT.md`：带确认日期的最近运行状态、当前未完成的工作及待验收事项；不把历史状态写成当前事实。
- `LOG.md`：重要操作与长期决策的当次事实；已完成事项不在 CURRENT 重复展开。
- `PITFALLS.md`：可复用的触发条件、原因和处理；尚未重新验证的问题明确标记为历史观察。
- `RUNBOOK.md`：可复用的操作命令和步骤；`DESIGN.md`：UI 设计经验与体验底线。
- 普通进度、工具日志、模拟失败和已核对的误报不归档；不能为了通过 Hook 而写记忆。
