# 数据库迁移索引

本目录中的旧迁移用于 Alembic revision 链兼容，不代表当前业务模型。日常开发请优先读取当前 ORM、API Schema 和领域文档。

## Agent 默认读取范围

1. 先读取本文件。
2. 新增迁移时只读取当前 head：`versions/0018_unify_record_relations.py`。
3. 仅在升级链、降级链或历史数据兼容测试失败时，沿 `down_revision` 逐个追溯相关迁移。
4. 不要一次性读取 `versions/` 下全部文件。

## Revision 摘要

| Revision | 作用 |
| --- | --- |
| 0001–0003 | 本地基础表、来源附件、审计 |
| 0004–0009 | 领域记录、提取运行、候选包、根空间与来源维护 |
| 0010–0013 | 业务时间字段逐步收敛为日期 |
| 0014 | 待办并入问题，简化记录类型 |
| 0015 | 采购并入账目并保留订单语义 |
| 0016 | 删除已迁移的采购/待办运行时详情表；保留 `legacy_todo_backup` 仅供 0014 降级 |
| 0017 | 永久删除采购订单，清理采购专属列，并统一真实资金流水完成状态 |
| 0018（当前 head） | 将记录关系统一为无方向的 `relates_to`，规范端点并合并重复关系 |

下一次新增迁移应以 `0018_unify_relations` 为 `down_revision`。当项目需要真正压缩迁移链时，应单独执行“基线迁移”任务，并同时验证空库安装、现有数据库升级、备份恢复和 `alembic_version` 兼容。
