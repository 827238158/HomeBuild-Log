# 技术决策记录

## 记录格式

### 2026-06-28 - 初始化 Agent 工作规范
- 决策：建立 `AGENTS.md`、`docs/` 和 `checklists/` 作为长期项目协作规范。
- 原因：让后续任务遵循按需检索、逐步执行、自检更新的流程。
- 影响范围：项目文档、任务执行流程、后续 Agent 协作方式。

### 2026-06-28 - 当前阶段只建立项目治理文档
- 决策：本阶段仅初始化项目文档、任务体系、检查清单和 `AGENTS.md`，不编写业务代码，不锁定技术栈。
- 原因：先固定产品问题、协作边界和可验证流程，避免技术选型早于需求澄清。
- 影响范围：仓库当前只包含 Markdown 文档；后续代码或依赖引入必须由新任务明确授权。
- 状态：初始化阶段决策已完成；当前仍保持只写文档，但已进入产品与技术规划阶段。

### 2026-06-28 - 采用事件主线与共享记录的概念模型
- 决策：以事件承载装修事实的时间主线；账目、施工问题、尺寸、决策、采购、调研和待办作为可关联领域记录；时间线、账本、问题看板和空间档案作为共享数据的多种投影视图。
- 原因：同一装修事实往往同时影响时间、费用、空间和行动项，共享记录可减少重复录入与视图冲突。
- 影响范围：后续需求拆分、数据建模、识别流程和界面设计。
- 状态：概念决策已确认；字段模型、关系基数和技术实现仍需要验证。

### 2026-06-28 - 自动识别采用人在回路原则
- 决策：系统自动生成的是可追溯的候选记录，用户可确认、修改、拆分、合并或拒绝；低置信度推断不得伪装成已确认事实。
- 原因：装修信息包含金额、质量问题和重要决策，错误自动入账或错误归档的代价较高。
- 影响范围：识别结果模型、交互流程、审计信息和验收标准。

### 2026-06-28 - 首版产品与部署边界
- 决策：首版为个人私用的响应式Web/PWA；Windows本地自托管，通过私有组网HTTPS访问，不开放公网注册和端口。
- 原因：兼顾电脑整理、手机现场录入、个人隐私和运维可控性。
- 影响范围：客户端形态、鉴权、部署、离线能力和安全测试。

### 2026-06-28 - 技术规划基线
- 决策：前端采用React、TypeScript和Vite PWA，后端采用Python与FastAPI，结构化数据采用SQLite，附件保存到本地文件目录。
- 原因：适合响应式交互、本地单用户部署、Python AI生态及低运维成本。
- 影响范围：后续应用骨架、接口、存储、测试和部署任务。
- 状态：规划已确认；依赖版本和具体配置须在实施任务中通过Context7验证。

### 2026-06-28 - 八类记录浅覆盖与共享实体
- 决策：首版覆盖事件、账目、施工问题、尺寸、决策、采购、调研和待办；空间、商家、材料、附件和项目阶段作为共享实体。
- 原因：真实样本证明一次描述会跨多种分类，而材料和空间会被多类记录复用。
- 影响范围：领域模型、AI提取协议、接口和页面导航。

### 2026-06-28 - 施工扩展表达方式
- 决策：施工进度、里程碑和验收测试先作为事件子类型；空间拆改由事件、决策和空间关联表达；材料不新增顶层记录类型。
- 原因：满足当前样本表达，同时避免在样本不足时过早增加顶层分类。
- 影响范围：事件类型、空间档案、材料档案和后续样本验证。

### 2026-06-28 - 采购与账目分离
- 决策：采购记录订单总额、商品和履约；账目记录每笔实际资金流；余额通过关联计算。
- 原因：样本001同时存在1100元订单和500元预付款，二者语义不同。
- 影响范围：账本、采购跟踪、金额计算和接口契约。

### 2026-06-28 - 即时预览与待确认箱
- 决策：AI提取后先展示即时预览，用户可立即确认或稍后在待确认箱处理；离线只能保存草稿。
- 原因：在低录入负担和事实准确性之间取得平衡。
- 影响范围：采集流程、候选状态、PWA离线边界和确认事务。

### 2026-06-28 - 可插拔AI与持久化识别任务
- 决策：使用统一AI适配协议；云端适配器显式启用；图片和OCR使用持久化任务与独立worker。
- 原因：便于切换云端/本地模型，避免供应商锁定，并保证耗时识别任务可重试。
- 影响范围：隐私、任务状态、模型评测和错误恢复。

### 2026-06-28 - 跨模型Agent采用单写者串行
- 决策：不建立固定多Agent团队；DeepSeek、Kimi、GPT等模型可轮流接手，但同一时刻只有`tasks/ACTIVE.md`中的Agent可以写入。
- 原因：减少上下文断裂、文件冲突和不同模型同时修改同一项目的风险。
- 影响范围：AGENTS规范、任务锁、交接记录和审查流程。
