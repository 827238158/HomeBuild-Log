# 代码与文档风格

## 当前适用范围
- 当前已有React、TypeScript、Vite、Vitest、FastAPI、SQLAlchemy、Alembic、pytest与Ruff工程；阶段1、阶段2和阶段3A均已完成。
- 前端代码位于`frontend/`，后端代码位于`backend/`，运行数据位于`.local-data/`。
- 当前业务日期精确到日，系统时间统一使用UTC，界面固定按北京时间展示；金额使用最小货币单位整数。
- 继续保持产品术语、领域语义、API契约、任务记录和决策文档一致。

## 代码风格
- Python使用Ruff检查，TypeScript使用严格类型检查；不得跳过失败检查提交结果。
- 不为小改动引入无关重构。
- Python目标版本为3.13；文本文件读写显式指定UTF-8，避免Windows中文环境下依赖默认编码。
- 前端不得重复实现账本金额、空间后代聚合、来源复核等服务端业务口径。
- 命令、依赖版本和接口行为只能记录已经由清单、源码或实际运行确认的内容。

## 命名规范
- 使用清晰、稳定、能表达业务含义的命名。
- 遵守当前语言和框架的惯用命名。
- 领域术语优先使用：事件、账目、施工问题、尺寸、决策、采购、调研、待办、空间、附件、来源、候选记录、正式记录。
- 同一概念只使用一个主名称；新增近义术语前先检查项目规格和架构文档。
- 时间字段必须区分业务发生日期`occurred_date`、来源录入时间`captured_at`和系统创建/更新时间；不得用默认日或默认时间伪装未知精度。

## 注释规范
- 关键步骤必须写简短中文注释，重点解释业务原因、边界和非显然取舍。
- 避免解释显而易见的语句。

## 错误处理规范
- 不吞掉异常。
- 错误信息应帮助定位问题。
- 识别失败、字段缺失、低置信度和事实冲突应保持可区分，不得统一伪装成成功结果。
- 面向用户的错误不得泄露密钥、内部路径、完整堆栈或敏感装修数据。
- FastAPI默认校验错误与项目自定义错误并存；文档不得把尚未统一实现的错误包络描述为当前事实。

## 测试规范
- 根据风险决定测试范围。
- 修改公共行为、API、数据结构或关键流程时必须考虑测试。
- 涉及金额计算、记录关联、状态变化、来源版本、删除影响、重复确认和权限的逻辑应优先覆盖边界测试。
- 后端测试使用pytest，前端组件测试使用Vitest；测试临时数据不得污染正式`.local-data/db`。
- 数据库迁移必须同时验证空库升级与已有数据转换；日期迁移不得凭空补造未知日期。

## 文档规范
- 文档记录长期有效的规则、架构、契约和流程。
- 临时过程不要写入长期文档。
- 文档默认使用简体中文和 UTF-8；命令、路径、标识符使用代码格式。
- 已确认事实、假设、候选方案和未知项必须明确区分；不确定内容标注「不确定」或「需要验证」。
- 架构/API/流程发生变化时同步更新对应文档和决策记录，不只在任务文件中留下结论。
- 已实现接口、已批准规划和探索性设想必须分段标注；不得把阶段4—5的计划写成当前能力。
- 接口字段、枚举、AI供应商顺序和运行命令应优先以当前源码、配置、迁移及依赖清单为准。
