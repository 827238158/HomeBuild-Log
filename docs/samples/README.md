# 真实装修事件样本说明

本目录保存用于验证 HomeBuild Log 业务分类与候选数据结构的真实装修事件。它属于产品研究证据，不是业务数据库，也不代表样本已转化为正式记录。

## 保存规则

1. 每条事件使用稳定编号 `RE-YYYYMMDD-NNN`；日期是样本收录日期，不代表事件发生日期。
2. 用户提供的文字完整放入“原始描述”代码块，不改写、不纠错、不补标点。
3. 图片或票据作为原始证据引用；仅记录实际收到的附件信息，不虚构文件名、内容或识别结果。
4. 原始描述与候选分析严格分区。后续用户纠正只更新分析和确认记录，不覆盖原文。
5. 没有提及的信息标为“未提及”；存在多种解释时标为“不确定”；需要用户回答时写入“待补充”。
6. 结构化记录类型是候选分类，不代表已经创建正式业务记录。

## 隐私提醒

- 样本可能含住宅照片、地址、姓名、电话、订单号或付款信息。用户可在发送前遮盖不影响业务分析的敏感信息。
- 不应为了脱敏而补写替代事实；脱敏内容按用户原样保留，例如“某小区”或“张师傅”。
- 未经用户明确提供，不推断家庭关系、身份、具体地址、支付账户或联系方式。

## 分析口径

每个信息项记录四部分：

- 候选值：原文直接表达或可明确解析出的内容。
- 原文依据：支持该候选值的最小原文片段。
- 确定性：`明确`、`不确定`、`未提及`。
- 待补充：为了形成可用记录，需要用户补充或确认的问题。

逐条检查以下信息，即使没有提及也要保留检查结果：

- 时间：发生、付款、计划、截止或相对时间。
- 空间：房屋、房间、区域、墙面、柜体、点位等位置。
- 人物：业主、家庭成员、工人、商家、设计师或其他参与者。
- 金额：报价、付款、退款、预算、单价、数量和币种。
- 尺寸：长度、宽度、高度、面积、厚度、数量及单位。
- 问题：现象、影响、责任、状态、证据和处理结果。
- 决策：候选方案、最终选择、理由、参与人和是否已确认。
- 采购：商品、规格、数量、商家、订单、交付和退换状态。
- 调研：待比较对象、问题、资料、结论和证据来源。
- 待办：动作、负责人、截止时间、前置条件和完成状态。

## 一事多记录判断

一条原始事件可产生零种、一种或多种候选记录。例如，同一句话可能同时描述付款、发现施工问题并要求师傅返工。分析时应分别列出候选记录，但保留它们对同一原始事件、附件、时间和空间的引用关系。

不得为了凑齐类型而创建没有原文依据的记录。

## 汇总原则

- 先积累逐条证据，再总结分类和字段；不能用预设字段强迫样本就范。
- 汇总时分别标记：被样本支持、边界冲突、可能缺失、仍需更多样本。
- 稳定结论经用户确认后，才考虑更新项目规格、概念架构或接口契约。
