# 路线图与跨模型Agent协作

## 路线图原则

- 先建立可追溯的手工记录闭环，再让AI加速录入。
- 每个阶段都有可独立验收的用户价值，不以“代码写完”作为完成标准。
- 阶段1、阶段2、阶段3A和阶段3B已经完成；阶段4和阶段5仍是规划，不代表已授权开发。
- 后续阶段必须由用户分别确认开始；任务默认采用轻量化流程，只有用户明确要求时才使用完整流程。

## 跨模型协作模型

DeepSeek、Kimi、GPT等模型不是固定团队成员，而是可替换的任务执行者。项目使用“一个用户负责人 + 一个当前写入Agent + 可选只读审查Agent”的最小结构。

### 当前写入Agent

- 在`tasks/ACTIVE.md`认领任务后才可修改项目。
- 只修改任务允许范围内的文件。
- 默认按轻量化流程负责实现、风险相称的检查、必要文档同步和活动日志；完整清单仅在用户明确要求完整流程时执行。
- 完成或交接时释放写入权。

### 只读审查Agent

- 可由另一模型承担，但不能编辑文件。
- 输出证据明确的风险和建议。
- 修复仍由当前写入Agent完成，避免并发写入。

### 用户负责人

- 决定任务优先级、重大产品选择和是否进入下一阶段。
- 可随时更换当前模型，但更换前必须完成任务交接记录。

## 活动任务锁

轻量化流程下，`tasks/ACTIVE.md`至少包含当前执行Agent、任务简述和状态；完整流程可进一步记录：

- 当前任务链接。
- 开始时间和状态。
- 允许修改的文件或目录。
- 是否允许只读审查。
- 释放或交接条件。

当文件显示“无活动写入任务”时，新Agent才可认领；如果任务仍被占用，新Agent必须保持只读，除非用户明确确认旧任务已经中止并完成交接。用户明确限定修改范围并授权不写任务记录时，可作为该次任务的例外，但不得扩大到其他文件。

## 标准交接内容（完整流程）

任务文件必须记录：

1. 已完成内容。
2. 修改文件清单。
3. 实际执行的命令、检查和结果。
4. 未完成内容和下一步。
5. 风险、不确定项和待用户确认事项。
6. 当前工作区是否存在未验收改动。
7. 是否已在`tasks/AGENT-ACTIVITY-LOG.md`追加记录。
8. `tasks/ACTIVE.md`是否已释放。

轻量化流程只强制在完成后追加一行活动日志并释放活动锁；如有未完成内容、风险或待确认事项，应在最终交付中明确说明。新Agent必须先读取活动锁和现有任务记录，再输出自己的`Need:`；上一模型的聊天摘要只能作为线索，不能替代项目文档。

## 文件冲突规则

- 单写者模式下禁止两个Agent同时编辑，即使文件不同。
- 只读审查不改变工作区。
- 用户要求切换模型时，当前Agent先停止新增修改并完成交接。
- 发现来源不明的改动时不得覆盖，应记录差异并请求用户决定。
