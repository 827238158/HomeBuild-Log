# 路线图与跨模型Agent协作

## 路线图原则

- 先建立可追溯的手工记录闭环，再让AI加速录入。
- 每个阶段都有可独立验收的用户价值，不以“代码写完”作为完成标准。
- 当前只规划，不代表已授权进入真实开发。
- 后续阶段必须分别创建任务并由用户确认开始。

## 阶段0：规划与样本验证

交付：

- 产品规格、架构、领域模型、交互、接口和协作文档。
- 真实事件样本及分类结论。
- 单写者任务锁、交接规范和Review门禁。

完成条件：样本001、004、007能走通领域模型，文档链接、术语和技术规划一致，仓库无业务代码。

## 阶段1：本地基础

目标：形成可运行但尚不依赖AI的本地数据底座。

交付：项目骨架、单用户会话、SQLite、附件目录、空间层级、来源保存、审计、导出和恢复验证。

门禁：必须先确定数据目录、附件限制、依赖版本、测试命令和备份位置。

## 阶段2：手工记录与核心视图

目标：即使没有AI，也能完整记录和检索装修事实。

交付：八类记录、共享实体、关联编辑、时间线、账本、问题看板、空间档案和基础搜索。

门禁：使用7条真实样本手工录入并核对多视图一致性。

## 阶段3：文本AI录入

目标：用户描述发生的事情，系统生成可追溯候选。

交付：AI适配协议、文本提取、原文依据、确定性、追问、即时预览、待确认箱和原子确认。

门禁：建立样本评测集；金额、问题和决策不得未经确认进入正式数据。

## 阶段4：图片票据与移动PWA

目标：支持装修现场的图片、票据和离线草稿。

交付：附件上传、持久化识别任务、OCR/视觉适配、PWA安装、离线草稿、同步去重和Tailscale Serve私有HTTPS访问。

门禁：验证识别失败恢复、手机同步、HTTPS、PWA更新和外部AI隐私提示。

## 阶段5：稳定化

目标：让长期个人档案可维护、可查找、可恢复。

交付：搜索优化、重复检测、批量导入、完整导出、每日备份、恢复演练、隐私审计和模型评测。

门禁：从空环境完成恢复，数据库、附件、来源和关联校验一致。

## 跨模型协作模型

DeepSeek、Kimi、GPT等模型不是固定团队成员，而是可替换的任务执行者。项目使用“一个用户负责人 + 一个当前写入Agent + 可选只读审查Agent”的最小结构。

### 当前写入Agent

- 在`tasks/ACTIVE.md`认领任务后才可修改项目。
- 只修改任务允许范围内的文件。
- 负责实现、检查、文档同步和修复审查意见。
- 完成或交接时释放写入权。

### 只读审查Agent

- 可由另一模型承担，但不能编辑文件。
- 输出证据明确的风险和建议。
- 修复仍由当前写入Agent完成，避免并发写入。

### 用户负责人

- 决定任务优先级、重大产品选择和是否进入下一阶段。
- 可随时更换当前模型，但更换前必须完成任务交接记录。

## 活动任务锁

`tasks/ACTIVE.md`必须包含：

- 当前任务链接。
- 当前执行Agent名称/模型。
- 开始时间和状态。
- 允许修改的文件或目录。
- 是否允许只读审查。
- 释放或交接条件。

当文件显示“无活动写入任务”时，新Agent才可认领；如果任务仍被占用，新Agent必须保持只读，除非用户明确确认旧任务已经中止并完成交接。

## 标准交接内容

任务文件必须记录：

1. 已完成内容。
2. 修改文件清单。
3. 实际执行的命令、检查和结果。
4. 未完成内容和下一步。
5. 风险、不确定项和待用户确认事项。
6. 当前工作区是否存在未验收改动。
7. `tasks/ACTIVE.md`是否已释放。

新Agent必须先读取任务文件和活动锁，再输出自己的`Need:`。上一模型的聊天摘要只能作为线索，不能替代项目文档。

## 文件冲突规则

- 单写者模式下禁止两个Agent同时编辑，即使文件不同。
- 只读审查不改变工作区。
- 用户要求切换模型时，当前Agent先停止新增修改并完成交接。
- 发现来源不明的改动时不得覆盖，应记录差异并请求用户决定。

## 后续任务池

按路线图顺序建立任务，不一次性启动全部阶段：

1. 数据目录、附件和备份需求确认。
2. 应用骨架与本地运行基线。
3. 领域模型与手工录入。
4. 核心可视化页面。
5. 文本AI适配与评测。
6. 图片票据与OCR。
7. PWA离线草稿与私有网络部署。
8. 搜索、导入导出和恢复演练。
