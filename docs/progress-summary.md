## 一、这个项目要做什么

装修过程中，你会遇到大量零散信息：昨天在光彩大市场定了花砖、今天发现主卧地砖破了一角、水电工说打压通过了、618 买的开关还没发货……

目前这些信息散落在聊天记录、手机相册和脑子里。**HomeBuild Log 的目标**：你只需要像聊天一样描述发生了什么，系统自动帮你整理成——

- **时间线**：装修到哪一步了，哪天做了什么
- **账本**：花了多少钱、还要付多少
- **问题看板**：有哪些施工问题、处理了没
- **空间档案**：每个房间用了什么材料、做了哪些决定

首版是个人私用的本地 Web 系统，所有数据在你自己电脑上，不经过任何云端。

## 三、阶段 1 为什么要拆成这些步骤

阶段 1 的目标是"一个能跑起来的本地系统骨架"。按依赖关系拆成 3 步子任务：

```
A. 单用户会话         登录/认证
        ↓  【没有登录，后面的接口全是裸奔，所以必须先做】
B. 来源与附件         文字录入 + 文件上传
        ↓  【数据从哪来？这是整个系统的唯一入口，所有后续功能都从这里读数据】
C. 审计记录           自动操作日志
        ↓  【数据有了之后，每次增改都必须留痕，装修金额和决策需要可追溯】
D. 导出恢复           已跳过（非开发阶段必需）
```

**关键原则**：每一步都在上一步可运行的基础上增加一层能力，做完一步就能验证一步，不做完 A 绝不开工 B。

## 五、启动后实际能做什么

打开两个终端，分别启动后端和前端：

```bash
# 终端 1：后端
cd backend
D:\Anaconda\envs\homebuild-log\python.exe -m fastapi dev app/main.py --host 127.0.0.1 --port 8000

# 终端 2：前端
cd frontend
npm run dev
```

浏览器访问 `http://127.0.0.1:5173`，体验流程：

```
┌─────────────────────────────────────────────────────────────┐
│ 1. 后端控制台打印管理员密码（如 a1b2c3d4...）              │
│ 2. 密码输入框 → 登录 → 进入主页（显示"本地服务运行正常"）  │
│ 3. 文本框中输入"今天去看了瓷砖"，点保存                     │
│ 4. 下方"最近记录"显示刚保存的内容 + 时间戳                  │
│ 5. 数据在 .local-data/db/homebuild-log.sqlite3 中可查      │
│ 6. 不登录直接访问任何 API → 401 拒绝                       │
│ 7. 每条创建操作都自动写入审计日志（GET /api/v1/audit）     │
└─────────────────────────────────────────────────────────────┘
```

## 六、下一步：阶段 2

阶段 2 的目标是"即使没有 AI，也能完整记录和检索装修事实"。核心是两件事：

### 2A. 八类业务记录

把 `source_entries`（纯文字"今天去看了瓷砖"）变成结构化数据：

| 记录类型 | 示例 |
|----------|------|
| 事件 | 2026-06-27 在光彩大市场选购瓷砖 |
| 账目 | 500 元预付款（支出） |
| 施工问题 | 主卧门口地砖小破裂 |
| 尺寸 | 60×120cm（材料规格，花砖） |
| 决策 | 确定不返工，用门套遮挡 |
| 采购 | 18 片花砖、总额 1100 元、2026-07-01 计划送达 |
| 调研 | 瓷砖颜色选浅灰还是中灰（比较依据 + 结论） |
| 待办 | 等待门套施工并复核遮挡效果 |

### 2B. 四个视图界面

| 视图 | 展示什么 |
|------|----------|
| 时间线 | 按日期排列所有事件，聚合关联的决策、账目和待办 |
| 账本 | 汇总已付/待付，每条资金流关联采购和决策 |
| 问题看板 | 按状态分组（进行中/已解决/已关闭），追踪处理过程 |
| 空间档案 | 按房间层级展示材料、尺寸、问题和决策 |

**阶段 2 不涉及 AI**——所有记录都是手工创建和填写的。AI 自动提取是阶段 3 的事。

## 七、方向确认

以下 5 条是整个项目不能动摇的基线，请确认是否仍然成立：

1. **本地优先**：所有数据在 `.local-data/`，不经过任何云端
2. **单用户私用**：没有多账户，没有权限体系
3. **AI 可选**：AI 只生成候选建议，最终确认必须由你手动完成
4. **一事多记录**：一条原始描述可以同时产生事件、账目、决策等多种记录
5. **原始事实不覆盖**：你的原始文字和图片永远不会被 AI 结果静默替换

如有任何一条需要调整，请现在提出。如果没有异议，随时可以说"开始阶段 2"。
