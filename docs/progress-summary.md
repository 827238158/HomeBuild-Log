## 一、快速上手——3 分钟走通第一条记录

### 1.1 启动

开两个终端：

```
# 终端 1（后端）
cd backend
D:\Anaconda\envs\homebuild-log\python.exe -m fastapi dev app/main.py --host 127.0.0.1 --port 8000

# 终端 2（前端）
cd frontend
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。

### 1.2 登录

后端首次启动时，控制台会打印一行 `admin password: a1b2c3d4...`（一串随机字符）。复制这段密码，粘贴到浏览器登录框，点**「登录」**。

> 每次重启后端密码不变；密码文件在 `.local-data/config/` 下，删掉重启会重新生成。

### 1.3 保存一条原文

登录后，你会看到一个大文本框，在里面输入：

```
今天去居然之家定了圣象地板，实木复合，总共 8500 元，送到楼下。
```

（可选）点**「选择文件」**传一张收据照片。然后点**「保存记录」**。

### 1.4 审核 AI 建议

保存成功后，下方会立即出现中文建议卡片。AI（或本地规则）会把你的文字拆成多条建议：

- 采购卡片：圣象地板，8500 元
- 账目卡片：支出 8500 元
- 待办卡片：确认送货时间

**明确项自动勾选了**，你不确定的内容不会勾。你可以直接在卡片上修改金额、标题等字段。

### 1.5 确认

点**「一键确认全部明确项」**——所有可信的建议一次性变成正式记录，存入数据库。

### 1.6 查看结果

切换到**「时间线」**Tab → 看到事件出现在对应日期下。切换到**「账本」**Tab → 看到 8500 的支出。

**完成！**这就是系统最核心的使用流程。

## 三、「录入」Tab 详解——这是最核心、也最容易困惑的地方

「录入」Tab 是最复杂的页面，从上到下分成 3 个大区：**来源区** → **AI 建议区** → **高级区**。下面逐一说明。

### 3.1 上半区：保存原文（来源录入）

| 操作 | 说明 |
|------|------|
| 文本框 | 输入你今天遇到的装修事项，自然语言即可，越详细越好 |
| 「选择文件」 | 可选，传一张图片或 PDF（JPG/PNG/WebP/HEIC/PDF，最大 50MB） |
| **「保存记录」** | **关键操作。** 把文字和附件一起存到数据库，作为"原始来源" |

保存成功后：
- 文本框清空 → 可继续录入下一条
- 下方"最近记录"列表出现新条目（文字摘要 + 时间）
- **系统自动开始用 AI 分析刚保存的来源**（如果你配了 API Key）或本地规则

> **如果附件上传失败**：来源已经保存成功，只是附件没传上去。此时会出现一个**「来源已保存，重试附件」**按钮，点它重试即可，不会重复创建来源。

### 3.2 下半区：选择来源和 AI 建议

在"最近记录"列表中 **点开任意一条来源**（或者用「选择原始来源」下拉菜单），就能对该来源进行拆解。

页面会展示几张**建议卡片**，每张卡片代表 AI（或本地规则）从你的文字中识别出的一条候选记录。

**卡片的组成部分：**

```
┌── ☑ 采购：圣象地板 ────────────────────────┐
│  原文依据：定了圣象地板...                     │
│  可信程度：明确 ●                              │
│  商品：圣象地板  数量：___  单价：___          │
│  订单总额：8500                                │
│  [补充更多信息 ▾]                              │
└──────────────────────────────────────────────┘
```

- **复选框**（☑）：勾上表示这条建议你想要确认
- **可信程度**：`明确`（AI 非常确定） / `可能` / `不确定`——全部默认勾选，你可手动取消
- **可编辑字段**：金额、标题、数量等可以直接在卡片上改
- **「补充更多信息」**：展开提示——空间、材料这些需要在下面高级区补充

### 3.3 确认按钮

卡片区下方有单个按钮：

| 按钮 | 做什么 | 什么时候用 |
|------|--------|-----------|
| **「确认所选」** | 处理你勾选的卡片，一次性创建正式记录 | 编辑完字段后点它，完成确认 |

> **确认是不可逆的**——确认后记录进入数据库，不能再退回候选状态。但你可以归档记录（在正式记录列表中点"归档"）。

### 3.4 AI 录入：分析方式 + 重新分析

在建议区上方有：

- **「选择原始来源」**下拉：切换当前处理哪条来源
- **「分析方式」**下拉：`自动主备并本地兜底` / `仅 AI` / `仅本地规则`
  - 默认自动模式：优先用 AI（如果你配了 API Key），AI 失败就自动回退到本地规则
  - `仅 AI`：只用 AI，不用本地规则
  - `仅本地规则`：断开 AI，只靠规则引擎
- **「重新分析」**：点这个才会真正**启动分析**。如果你只改了"分析方式"没点"重新分析"，什么都不会发生

> **每次保存来源时系统会自动分析一次**，所以刚保存完一般不需要手动点"重新分析"。只有你想换分析方式、或者上次分析失败了，才需要点。

### 3.5 手工录入

折叠在**「▸ 手工录入」**下方。这是**备选路径**——当 AI 建议不够准确，或者你想自由创建记录时使用。每个输入框都有随记录类型变化的中文示例；示例会在开始输入时消失，不会作为真实数据提交。

展开后是一个表单：

| 字段 | 说明 |
|------|------|
| 记录类型 | 下拉选：事件/账目/施工问题/尺寸/决策/采购/调研/待办 |
| 状态 | 根据类型不同，状态选项不同（如事件：planned/occurred/completed） |
| 标题 | 必填，例如"主卧门口地砖破裂" |
| 字段 A/B/C | 按所选类型显示不同输入框（如采购显示商品名/数量/总金额） |
| 空间、材料、参与者、装修阶段 | 从已建立的共享档案中选择 |
| **「创建正式记录」** | 提交，直接写入数据库，不走 AI 建议流程 |

> **手工创建的记录和 AI 确认的记录是平等的**——都会出现在时间线、账本等视图中。区别只是来源不同（一条有 AI 建议记录，一条直接创建）。

### 3.6 空间与共享档案

折叠在**「▸ 空间与共享档案」**下方。

空间就是"你家有哪些房间/区域"——比如"主卧""卫生间""卫生间-淋浴区"。共享档案包括材料、商家、参与者（工人设计师）、装修阶段。

系统会自动提供根空间**“整套房屋”**。新增房间时默认把它作为上级，因此第一次创建“主卧”也不需要先手工创建房屋；最后一个根房屋不能删除。

**为什么要先在这里建立**？因为在手工创建记录时，需要选择空间、材料这些信息。如果不提前建好，下拉菜单是空的。

| 操作 | 说明 |
|------|------|
| 空间名称 + 类型 + 上级空间 → **「新增空间」** | 创建空间层级（房屋→房间→局部构件/表面）；例如主卧的上级是房屋 |
| 实体类型 + 名称 → **「新增{类型}」** | 创建材料/商家/参与者/阶段；材料还可填写品牌，列表显示“品牌 · 名称” |
| 已有空间/档案 → **「删除」** | 仅能永久删除未被正式记录使用且没有下级空间的误建项目；操作前会再次确认 |

> **AI 建议不会自动创建空间和材料**。如果你的文字中出现了"主卧""厅"这类词，但你没在空间档案里建"主卧"，AI 建议卡片上会提示"空间未指定"。你需要先在“空间与共享档案”中建好空间，再重新分析。

### 3.7 记录之间的关联

折叠在**「▸ 记录之间的关联（一般无需手动设置）」**下方。系统通常会自动建立关联；只有自动关联不准确时才需要手工调整。关联会影响时间线串联、采购待付计算和问题看板下一步。

记录之间可以建立关系。例如：
- “500元预付款”**用于支付**“花砖采购”
- “门套遮挡方案”**解决**“地砖破裂问题”
- “到货后验收”**跟踪送货**“花砖采购”

| 操作 | 说明 |
|------|------|
| 第一条记录 + 中文关系 + 第二条记录 → **「建立关联」** | 按页面实时预览的方向建立关联；下拉同时显示记录类型和标题 |
| 已有关系列表 → **「移除」** | 确认后删除关联；页面会提示可能影响的联动视图 |

## 四、其他 5 个 Tab 说明

### 4.1 「时间线」Tab

按日期排列所有**事件**记录，每一条事件下展开显示关联的决策、账目、采购等。

- 顶部筛选栏：关键词、事件类型、空间、阶段、日期范围
- **「应用筛选」**后重新加载
- 点击任何一张卡片 → 弹出右侧**详情面板**

### 4.2 「账本」Tab

财务汇总视图。展示：

- **汇总卡片**：采购总额 / 实际支出 / 退款 / 待付
- **采购付款情况**：每笔采购 + 已付金额 + 待付金额
- **资金流水**：每笔账目明细
- **「应用筛选」**可按日期范围过滤

> 待付 = 采购总额 - 已付的账目金额，这是系统算出来的，不是你自己填的。

### 4.3 「问题」Tab

施工问题的**看板视图**，分 5 列：

| 列名 | 含义 |
|------|------|
| 发现 | 刚上报，还没处理 |
| 处理中 | 正在处理 |
| 等待 | 等材料/等人，暂时无法推进 |
| 已解决 | 方案已执行 |
| 已关闭 | 你复核确认没问题 |

每张卡片显示：问题标题、现象描述、所在空间。**状态下拉**可以直接在卡片上改变状态，不用点进去编辑。

### 4.4 「空间」Tab

按空间层级查看每个房间/区域的**完整档案**。

选择空间后展示：
- 面包屑（层级路径：房屋 > 卧室 > 主卧）
- 统计：该空间下的记录数、未关闭问题、尺寸、材料
- 按类型分组的记录列表

### 4.5 「搜索」Tab

全局搜索。可搜索：
- **正式记录**（标题、描述）
- **原始来源**（原文文字）
- **材料、商家、空间**

组合条件：关键词 + 记录类型 + 状态 + 日期范围。

### 4.6 记录详情侧面板

在任何 Tab 中点卡片，右侧滑出一个面板，展示该记录的完整信息：

- 标题、类型、状态、空间
- 原始来源的原文摘录
- 关联的其他记录
- 操作审计历史（谁、什么时间、改了啥）

点**「关闭」** 或点击面板外部区域关闭。

## 五、常见困惑（FAQ）

### Q1：只有一个「确认所选」按钮，那确认时发生了什么？

点「确认所选」后，系统会为**你勾选的每张卡片**创建一条正式记录，同时建立它们之间的关联关系。编辑过的字段（金额、标题等）会随确认一起提交。

> 确认是不可逆的。确认后会变成正式记录，不能再退回候选状态，但可以归档隐藏。

### Q2：为什么所有建议都默认勾选了？

全部默认勾选，因为大多数建议你都会想确认。如果某条不需要，手动取消勾选即可。

账目金额、施工问题、决策这三种高风险类型会显示橙色警告，提醒你注意。

### Q3：已保存记录里的状态、修改和归档是什么意思？

“状态”表示事情当前进展；例如决策“待确认”代表还没最终决定，待办“待处理”代表还没开始。**「修改标题/状态」**只调整名称和进展；**「归档并隐藏」**不会删除数据，只会从常用视图隐藏，之后可以**「恢复显示」**。

### Q4：手工录入和 AI 录入是什么关系？

**两个独立路径，结果一样。**

- AI 录入：保存原文 → 自动分析 → 你点确认 → 生成记录（推荐）
- 手工录入：展开表单 → 参考框内示例手动填写 → 点创建 → 直接生成记录（备选）

两条路径生成的记录在数据库中是完全平等的，都会出现在时间线、账本等视图中。

### Q5：「分析方式」下拉改完后为什么没变化？

因为**改下拉不会触发分析**。你需要再点一下旁边的**「重新分析」**按钮才会生效。

### Q6：保存时附件上传失败，提示"来源已保存，重试附件"？

这表示文字已经保存成功了，只是照片没传上去。点那个按钮重试附件上传即可，不会重复创建来源。

### Q7：为什么没有删除按钮？

设计原则：原始事实不覆盖、不删除。装修涉及金额和重要决策，误删后无法追溯。如果录入有误，你可以**归档**（隐藏）它，但不能物理删除。

## 六、关键设计逻辑

### 6.1 为什么先本地规则后 AI

本地规则不联网，即时出建议。三个意图：阶段 3 之前已有可用体验；AI 结果可跟本地规则交叉校验；断网时本地规则兜底。AI 只生成候选，最终确认由你手动完成。

### 6.2 为什么一事多记录

一句"定了花砖，付了 500 预付款"同时包含事件、采购、账目。一条来源可同时产生多条不同类型记录。这是"视图不是副本"的前提——时间线、账本、看板从同一个事实池读数据。

### 6.3 为什么公共 records 表 + 八张详情表

公共字段在一张表里，查询快；每种记录的独特字段放各自详情表，避免宽表空字段膨胀。

### 6.4 为什么共享实体单独建表

空间、材料、商家被多种记录复用。集中管理，改一处名全局生效。

## 七、方向确认（基线不变）

1. **本地优先**：所有数据在 `.local-data/`，不经过任何云端
2. **单用户私用**：没有多账户，没有权限体系
3. **AI 可选**：AI 只生成候选建议，最终确认必须由你手动完成
4. **一事多记录**：一条原始描述可以同时产生事件、账目、决策等多种记录
5. **原始事实不覆盖**：你的原始文字和图片永远不会被 AI 结果静默替换
