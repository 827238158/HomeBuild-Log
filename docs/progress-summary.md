## 一、快速上手——3 分钟走通第一条记录

### 1.1 启动

开两个终端：

```
# 终端 1（后端）
cd backend
D:\Anaconda\envs\homebuild-log\python.exe -m fastapi dev app/main.py --host 127.0.0.1 --port 8000

# 终端 2（前端）
cd frontend
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。

### 1.2 登录

后端首次启动时，控制台会打印一行 `admin password: a1b2c3d4...`。复制这段密码，粘贴到浏览器登录框，点**「登录」**。

> 每次重启后端密码不变；密码文件在 `.local-data/config/` 下，删掉重启会重新生成。

### 1.3 保存一条原文

登录后，默认进入**概览**页面。在顶部录入区的文本框中输入：

```
今天去居然之家定了圣象地板，实木复合，总共 8500 元，送到楼下。
```

（可选）点附件选择器传一张收据照片（支持 JPG/PNG/WebP/HEIC/PDF，最大 50MB）。点**「保存并分析」**即可保存原文并自动触发 AI 分析。

如果只想保存暂不分析，也可以点**「保存记录」**。

### 1.4 审核 AI 建议

保存并分析后，文本框清空，下方"智能拆分"区域会显示候选卡片。AI（或本地规则）会把你的文字拆成建议记录：

- 账目卡片：支付地板款 8500 元
- 事件卡片：选购地板事件

全部未确认候选默认勾选。你可以直接在卡片上修改类型（通过下拉框）、金额、标题等字段，也可以取消勾选不需要的候选。

### 1.5 确认

点**「确认所选」**——所有勾选的候选一次性变成正式记录，存入数据库。

### 1.6 查看结果

切换到**「时间线」**→ 看到事件出现在对应日期下。切换到**「账本」**→ 看到支出金额和商家分布。

**完成！**这就是系统最核心的使用流程。

## 三、「录入」Tab 详解——最核心的页面

录入 Tab 从上到下分为：**来源录入区** → **智能拆分区** → **空间与共享档案** → **记录关联**。

### 3.1 上半区：保存原文

| 操作 | 说明 |
|------|------|
| 文本框 | 输入装修事项，自然语言即可，越详细越好 |
| 附件选择器 | 可选，传一张图片或 PDF |
| **「保存记录」** | 保存来源到数据库，不触发分析 |
| **「保存并分析」** | 保存来源后立即按默认方式触发 AI/本地规则分析 |

保存成功后，文本框清空，来源列表新增一条。

> 附件上传失败不影响来源保存。此时会出现「来源已保存，重试附件」按钮，点它重试。

### 3.2 智能拆分区

保存并分析后，在录入区下方自动加载来源列表和候选卡片。

- **来源列表**：显示每条来源的分析状态（待处理候选数 / 已确认 / 已忽略）。
- **筛选分析方式**：自动主备并本地兜底 / 仅 AI / 仅本地规则。
- **「重新分析」**：用当前选择的分析方式重新运行提取。
- **候选卡片**：每张显示记录类型、标题、原文依据和可信程度。通过顶部下拉框可切换类型，字段会动态变化。

### 3.3 确认按钮

| 按钮 | 做什么 | 什么时候用 |
|------|--------|-----------|
| **「确认所选」** | 将当前勾选的候选一次性创建为正式记录 | 编辑完字段后点它完成确认 |

> 确认是不可逆的。确认后记录进入数据库，不能再退回候选状态，但可以归档隐藏。

### 3.4 手工追加记录

在候选卡片区底部有**「+ 添加手工记录」**按钮，点击后添加一张与 AI 候选同形的空白候选卡片，可自由选择类型并填写字段，与 AI 候选一起勾选确认。

### 3.5 空间与共享档案

维护房屋→房间→局部构件的空间层级，以及材料、商家、参与者和装修阶段档案。

系统自动提供根空间**"整套房屋"**。新增房间默认把"整套房屋"作为上级；最后一个根房屋不能删除。材料档案可填写品牌，列表显示"品牌 · 名称"。只有未被正式记录使用的档案才允许物理删除。

### 3.6 记录之间的关联

显示中文关系名称和方向说明，建立、查看和移除记录之间的关联。

## 四、其他页面说明

### 4.1 「概览」

展示未关闭问题、逾期及未来7天事项、最近动态和按装修阶段分布的事项。阶段分布使用环形图。点击可进入筛选后的对应视图。

### 4.2 「时间线」

按发生日期分组排列所有事件，未知日期归入"时间待补充"。支持关键词、记录类型、空间、阶段和日期范围筛选。事件节点可展开查看直接关联记录。

上方图表：记录数量趋势（折线图）、类型分布（环形图）和日期待补充数量（横向柱状图）。点击图表可筛选时间线明细。

### 4.3 「账本」

财务汇总视图：

- **统计卡片**：实际支出 / 退款与收入 / 待付金额 / 净支出
- **资金构成环形图**：付款 / 退款 / 收入
- **月净支出趋势折线图**：按时序展示资金流向
- **商家金额分布横向柱状图**：按商家展示净金额
- **有效流水明细列表**：支持商家、空间、阶段和日期范围筛选

> 净支出 = 实际支出 - 退款 - 收入。只有已出账付款和已入账退款/收入参与统计。

点击图表可打开抽屉或底部弹层查看同口径明细。

### 4.4 「问题」看板

三列看板：**待处理** → **处理中** → **已完成**。可通过空间筛选。

每张卡片显示：标题、现象、所在空间和处理状态下拉框。卡片可展开查看关联记录和附件。

上方图表：状态分布（环形图）、空间分布（横向柱状图）和严重程度分布。

### 4.5 「空间」档案

按空间层级查看每个房间/区域的完整档案。选择空间后展示：

- 面包屑导航（层级路径）
- 统计卡片：记录数、未关闭问题、尺寸、材料和净支出
- 记录类型分布和问题状态分布图表
- 按类型分组的记录列表

### 4.6 「记录分析」

统一分析六类记录。通过类型标签切换：

- **事件**：类别分布 + 状态分布 + 时间趋势
- **账目**：付款/退款/收入状态分布 + 金额分布 + 商家分布
- **问题**：状态 + 严重程度 + 空间分布
- **尺寸**：测量角色 + 单位分布
- **决策**：状态分布 + 时间趋势
- **调研**：状态分布 + 时间趋势

### 4.7 「智能分析」

展示 AI 运行数据：

- 默认最近30天，可选7天/30天/90天/全部
- 摘要卡：请求数、成功率、回退率、平均耗时、总 token
- 图表：请求趋势、耗时趋势、token 趋势、最终引擎分布、错误类型分布
- 安全明细表：时间、请求方式、最终模型、结果、耗时和错误摘要
- 不展示完整 prompt、原始响应或 API Key

### 4.8 「搜索」

全局搜索，结果按来源、正式记录、材料、商家和空间分组。支持关键词和结构化条件（类型、空间、阶段、状态、日期范围）。

### 4.9 记录详情

点击任何记录卡片，右侧滑出详情抽屉：

- 查看态：展示标题、类型、状态、空间、发生日期、来源证据、关联记录和审计历史
- 编辑态：修改状态、发生日期、空间、参与者、阶段和类型专属字段（类型和原始来源不可改变）
- 物理删除需二次确认

## 五、关键设计逻辑

### 5.1 六类记录

当前系统支持六类正式记录：事件、账目、问题、尺寸、决策和调研。
- 账目仅包含付款、退款和收入，统一使用人民币。
- 待办和施工问题已统一为"问题"，使用待处理/处理中/已完成三状态。
- 采购已并入账目，不再作为独立类型。

### 5.2 为什么一事多记录

一句"定了花砖，付了500预付款"同时包含事件和账目。一条来源可产生多条不同类型记录。时间线、账本、看板从同一个事实池读数据。

### 5.3 人在回路

AI或本地规则只生成候选卡片。用户检查证据和确定性、修改字段、勾选确认后，才以原子事务创建正式记录。

### 5.4 为什么公共 records 表 + 类型详情表

公共字段在一张表里查询快；每种记录的独特字段放各自详情表，避免宽表空字段膨胀。

## 六、方向确认（基线不变）

1. **本地优先**：所有数据在 `.local-data/`，不经过任何云端
2. **单用户私用**：没有多账户，没有权限体系
3. **AI 可选**：AI 只生成候选建议，最终确认由你手动完成
4. **一事多记录**：一条原始描述可同时产生多种记录
5. **原始事实不覆盖**：原始文字和图片永远不会被 AI 结果静默替换
