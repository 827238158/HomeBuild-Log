# HomeBuild Log 架构说明

## 架构基线

系统采用本地优先的响应式Web/PWA形态：Windows电脑运行本地服务和持久化存储，电脑与手机通过私有网络访问。首版为单用户，不开放公网。

技术规划基线：

- 前端：React、TypeScript、Vite及PWA能力。
- 后端：Python与FastAPI，提供REST/OpenAPI接口。
- 数据：SQLite保存结构化数据，本地文件目录保存原始附件和导出包。
- AI：统一适配接口，可连接云端或本地文本、视觉、OCR模型。
- 私有访问：使用[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)提供私有组网HTTPS；禁止使用公网暴露模式。

具体依赖版本在进入开发任务时通过Context7核对并记录，本文件不锁定未经验证的版本号。

## 系统边界

### 当前实现状态

- 阶段 1 已实现登录、来源/附件和审计底座。
- 阶段 2A 已实现单一默认项目、空间层级、材料/商家/参与者/装修阶段、八类正式记录及显式记录关系。
- 已实现DeepSeek主、MiMo备的OpenAI兼容文字提取、逐次运行日志、持久化`CandidateBundle`与原子确认；`local-rule-v1`保留为无Key、失败和断网兜底。
- 正式记录使用公共`records`表与八张类型详情表；多维尺寸使用`measurement_values`子表，所有正式记录至少关联一个`SourceEntry`。
- 阶段 2B 已建立共享只读投影层及时间线、账本、问题看板、空间聚合档案、基础搜索和统一详情，并已通过用户亲自验收。
- 文本AI阶段3A已实现；追问/拆分/合并/拒绝、ECharts运行可视化、OCR、离线草稿、搜索优化和导出恢复仍是后续阶段能力。

```text
电脑/手机 PWA
    ↓ 私有 HTTPS
本地 Web/API 服务
    ├─ 领域与确认服务
    ├─ 查询与多视图服务
    ├─ 持久化识别任务/Worker
    ├─ 可插拔 AI/OCR 适配器
    └─ 备份、导出与审计
          ↓
    SQLite + 本地附件目录
```

- 浏览器只保存界面状态和离线录入草稿，不是正式数据的权威来源。
- 本地API是正式记录、关联、审计和备份的唯一写入入口。
- 外部AI只接收当前适配器被允许处理的输入，不能直接访问数据库或写入正式记录。

## 主要模块

### 采集与来源

- 接收文本、图片、票据和用户补充说明。
- 先创建不可静默覆盖的`SourceEntry`和附件元数据，再进行识别。
- 对附件计算稳定校验值，用于去重、完整性检查和恢复验证。

### 识别任务与AI适配

- 文本可在请求内快速提取，也必须保留提取运行记录。
- 图片、票据和OCR创建持久化任务，由独立worker处理。
- 适配器负责把不同模型响应转换为统一候选协议，不允许模型响应直接成为正式记录。
- HuggingFace不可用时可评估ModelScope同款或等价模型，但必须核对架构、用途、权重格式和适配库。

### 候选确认

- `CandidateBundle`包含一条来源产生的全部候选记录、字段依据、确定性和待补充问题。
- 用户可修改、拆分、合并、拒绝或暂存候选。
- 一次确认在单个事务中创建多条记录及关联；失败时整体回滚，不产生半套数据。
- 当前本地规则建议直接生成同形的可编辑候选；只有明确项默认选中，确认键在项目内唯一并用于幂等重试。

### 领域记录

- 管理事件、账目、施工问题、尺寸、决策、采购、调研和待办。
- 空间、材料、商家、附件和项目阶段作为共享实体。
- 记录之间通过显式关系连接，不用复制文本维持联系。

### 查询与可视化

- 查询投影集中批量加载来源、空间、材料、参与者、阶段、附件和类型详情；前端只负责筛选与展示，不复制金额或空间聚合规则。
- 时间线按事件时间、精度和阶段排序，并聚合关联记录。
- 账本组合采购总额与实际资金流水，计算已付和待付。
- 问题看板按问题状态投影，不改变问题本身。
- 空间档案按层级聚合尺寸、材料、问题、决策和事件。
- 首版时间线、看板、房间卡片和账本摘要使用React组件及基础HTML/CSS/SVG，不引入交互户型图。

### 搜索、审计与数据管理

- 搜索覆盖标题、描述、原始来源和必要的结构化字段，并支持时间、空间、类型和状态过滤。
- 当前基础搜索使用SQLite普通匹配，不引入FTS、模糊排名或重复检测；这些优化保留至阶段 5。
- 记录创建、修改、确认、拒绝、归档和恢复均写审计信息。
- 删除默认采用可恢复归档；原始来源和审计记录不能被普通编辑流程物理删除。
- 导出包包含数据库、附件、清单、版本和校验信息。

## 核心数据流

### 在线文字录入

1. 用户提交文字。
2. 服务保存`SourceEntry`。
3. 显式启用且配置Key时按DeepSeek→MiMo生成持久化`CandidateBundle`；主备失败或未配置时回退本地规则，每个候选附带原文依据和确定性。
4. 前端展示即时预览；用户确认候选。
5. 确认事务生成多条正式记录和`RecordRelation`。
6. 时间线、账本、看板和空间档案读取新的共享记录。

### 图片或票据录入

1. 服务保存附件、校验值和来源。
2. 创建持久化识别任务并返回任务状态。
3. worker调用OCR/视觉适配器，失败时记录原因并允许重试。
4. 识别成功后生成候选，不直接写正式记录。

### 离线录入

1. PWA仅把文字、附件引用和本地创建时间保存为离线草稿。
2. 恢复私有网络连接后上传草稿并创建正式来源。
3. 上传成功前不得展示为已确认记录；重复同步通过客户端草稿ID和幂等键避免重复。

## 存储规划

- SQLite：结构化记录、候选、关系、任务、配置和审计。
- 附件目录：按稳定ID或内容校验值组织原始文件，不依赖用户上传文件名作为唯一标识。
- 缩略图/派生文件：可重新生成，与原始附件分区存放。
- 数据目录：固定为项目根目录`.local-data/`；SQLite、附件、模型、备份和导出不得写入项目外或C盘默认缓存。
- 目录划分：`db/`、`attachments/originals/`、`attachments/derived/`、`models/`、`backups/`和`exports/`相互分区并全部忽略Git。
- 备份：规划为每日生成本地备份并保留30天；支持手动完整导出、校验和恢复演练。自动备份尚未实现。

## 安全与隐私

- 单一本地管理员账户，无公开注册。
- 私有组网设备边界加应用会话保护；不得仅依赖“知道地址”作为鉴权。
- 使用Tailscale Serve私有HTTPS，不启用Funnel等公网暴露能力。
- 云端AI适配器默认关闭，启用时展示供应商、将发送的数据类型和隐私提示。
- 日志不记录完整原始票据、密钥、访问令牌或不必要的个人信息。
- 配置和导出中的密钥不得进入普通Markdown、日志或备份清单明文区。

## 可靠性约束

- 正式记录、候选确认和关系创建必须具备事务性。
- 金额使用精确表示，不能用二进制浮点数保存货币。
- 时间保留原文、规范化值、时区和精度；未知日期部分不能用默认值伪装。
- 尺寸必须记录对象、单位、方向、是否近似及语义角色。
- 识别任务重试必须幂等；同一来源可有多次提取运行，但只能明确选择一个结果进入确认。

## 不允许随意改动的边界

- 原始来源不可被AI结果或后续纠错覆盖。
- AI候选与用户确认事实必须可区分。
- 多视图不得拥有独立事实副本。
- 账目表示真实资金流，采购表示订单与履约；不得混成单一金额字段。
- 正式接口、领域状态和破坏性数据变化必须先更新契约与决策记录。
