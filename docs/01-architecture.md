# HomeBuild Log 架构说明

## 架构基线

系统采用本地优先的响应式Web形态：Windows电脑运行本地服务和持久化存储，当前通过本机浏览器访问。目标形态是在电脑与手机之间通过私有网络访问，并增加PWA能力；首版为单用户，不开放公网。

技术规划基线：

- 前端：React、TypeScript和Vite；响应式Web已实现，PWA安装与离线能力尚未实现。
- 后端：Python与FastAPI，提供REST/OpenAPI接口。
- 数据：SQLite保存结构化数据，本地文件目录保存原始附件；导出包属于阶段5计划。
- AI：统一文本适配接口，当前可连接MiMo和DeepSeek的OpenAI兼容接口，并以本地规则兜底；视觉和OCR仍是规划能力。
- 私有访问（计划）：使用[Tailscale Serve](https://tailscale.com/docs/features/tailscale-serve)提供私有组网HTTPS；禁止使用公网暴露模式。

具体依赖版本在进入开发任务时通过Context7核对并记录，本文件不锁定未经验证的版本号。

## 系统边界

### 当前实现状态

- 阶段 1 已实现登录、来源/附件和审计底座。
- 阶段 2A 建立了八类记录；当前通过迁移将待办统一为“问题”、将采购统一为账目子类型，产品层保留六类正式记录及显式记录关系。
- 已实现默认按MiMo、DeepSeek顺序尝试的OpenAI兼容文字提取、逐次运行日志、持久化`CandidateBundle`与原子确认；供应商顺序可通过本地配置覆盖，`local-rule-v1`保留为无Key、失败和断网兜底。
- 正式记录使用公共`records`表与八张类型详情表；多维尺寸使用`measurement_values`子表，所有正式记录至少关联一个`SourceEntry`。
- 阶段 2B 已建立共享只读投影层及时间线、账本、问题看板、空间聚合档案、基础搜索和统一详情，并已通过用户亲自验收。
- 文本AI阶段3A和全项目可视化阶段3B已完成；当前前端导航为概览、录入、时间线、账本、问题、空间、记录分析、智能分析和搜索。ECharts按需模块用于核心视图、六类正式记录和AI运行数据；OCR、PWA安装、离线草稿、搜索优化和导出恢复仍是后续阶段能力。

```text
本机响应式 Web（手机私网/PWA计划）
    ↓ 当前本机 HTTP / 计划私有 HTTPS
本地 Web/API 服务
    ├─ 领域与确认服务
    ├─ 查询与多视图服务
    ├─ 文本提取运行与候选确认
    ├─ 可插拔文本 AI 适配器
    └─ 来源维护、查询投影与审计
          ↓
    SQLite + 本地附件目录
```

- 浏览器当前只保存界面状态和登录令牌，不是正式数据的权威来源；离线录入草稿仍是阶段4计划。
- 本地API是当前正式记录、关联与审计的唯一写入入口；未来备份与导出也必须通过受控本地服务完成。
- 外部AI只接收当前适配器被允许处理的输入，不能直接访问数据库或写入正式记录。

## 主要模块

### 采集与来源

- 接收文本、图片、票据和用户补充说明。
- 先创建不可静默覆盖的`SourceEntry`和附件元数据，再进行识别；用户显式修改递增来源版本并使旧候选失效。
- 来源删除先返回影响统计；确认后删除来源专属候选、提取、附件和独占正式记录，多来源记录仅解除当前来源，审计永久保留。
- 对附件计算稳定校验值，用于去重、完整性检查和恢复验证。

### 识别任务与AI适配

- 文本可在请求内快速提取，也必须保留提取运行记录。
- 当前只持久化文本提取的每次引擎尝试。图片、票据和OCR的持久化任务与独立worker尚未实现。
- 适配器负责把不同模型响应转换为统一候选协议，不允许模型响应直接成为正式记录。
- HuggingFace不可用时可评估ModelScope同款或等价模型，但必须核对架构、用途、权重格式和适配库。

### 候选确认

- `CandidateBundle`包含一条来源产生的全部候选记录、字段依据、确定性和警告。
- AI自动补全候选字段；用户可修改类型与字段、追加同形手工记录，并确认所选候选。
- 一次确认在单个事务中创建多条记录及关联；失败时整体回滚，不产生半套数据。
- 当前本地规则建议直接生成同形的可编辑候选；前端默认勾选全部未确认候选，仍由用户检查、编辑或移除后确认。确认键在项目内唯一并用于防止重复创建。

### 领域记录

- 管理事件、账目、问题、尺寸、决策和调研；账目只包含付款、退款和收入。
- 空间、材料、商家、附件和项目阶段作为共享实体。
- 记录之间通过显式关系连接，不用复制文本维持联系。

### 查询与可视化

- 查询投影集中批量加载来源、空间、材料、参与者、阶段、附件和类型详情；前端只负责筛选与展示，不复制金额或空间聚合规则。
- 时间线按有效业务日期倒序分组，未知日期进入“时间待补充”，并在事件节点聚合直接关联记录。
- 账本分别统计付款、退款和收入；净支出统一为付款减退款与收入。
- 服务端分析模块在现有只读投影上提供概览、核心视图`analytics`、统一记录分析和AI请求级分析；图表不得复制业务事实或在前端重算金额、空间继承和状态口径。
- 账目与采购保留`currency`兼容字段但接口只接受`CNY`，账本按单一人民币口径汇总；历史非人民币数据不会被静默转换。
- 问题看板按问题状态投影，不改变问题本身。
- 空间档案按层级聚合尺寸、材料、问题、决策和事件。
- 首版时间线、看板、房间卡片和账本摘要使用React组件及基础HTML/CSS/SVG，不引入交互户型图。

### 搜索、审计与数据管理

- 搜索覆盖标题、描述、原始来源和必要的结构化字段，并支持时间、空间、类型和状态过滤。
- 当前基础搜索使用SQLite普通匹配，不引入FTS、模糊排名或重复检测；这些优化保留至阶段 5。
- 记录创建、修改、确认、归档和恢复均写审计信息。
- 正式记录日常清理采用可恢复归档；原始来源只有通过影响预览和二次确认的专用流程才能安全级联删除，审计记录不能删除。
- 计划中的导出包包含数据库、附件、清单、版本和校验信息；当前尚无导出接口。

## 核心数据流

### 在线文字录入

1. 用户提交文字。
2. 服务保存`SourceEntry`。
3. 显式启用且配置Key时按本地`provider_order`尝试云端供应商；默认顺序为MiMo→DeepSeek，全部失败或未配置时回退本地规则。每个成功结果都会生成持久化`CandidateBundle`，候选附带原文依据和确定性。
4. 前端展示即时预览；用户确认候选。
5. 确认事务生成多条正式记录和`RecordRelation`。
6. 时间线、账本、看板和空间档案读取新的共享记录。

### 图片或票据录入（计划，尚未实现）

1. 服务保存附件、校验值和来源。
2. 创建持久化识别任务并返回任务状态。
3. worker调用OCR/视觉适配器，失败时记录原因并允许重试。
4. 识别成功后生成候选，不直接写正式记录。

### 离线录入（计划，尚未实现）

1. PWA仅把文字、附件引用和本地创建时间保存为离线草稿。
2. 恢复私有网络连接后上传草稿并创建正式来源。
3. 上传成功前不得展示为已确认记录；重复同步通过客户端草稿ID和幂等键避免重复。

## 存储规划

- SQLite：结构化记录、来源、候选、提取运行、关系和审计；机密配置保存在`.local-data/config/secrets.json`，不进入数据库。
- 附件目录：按稳定ID或内容校验值组织原始文件，不依赖用户上传文件名作为唯一标识。
- 缩略图/派生文件：可重新生成，与原始附件分区存放。
- 数据目录：固定为项目根目录`.local-data/`；SQLite、附件、模型、备份和导出不得写入项目外或C盘默认缓存。
- 目录划分：`db/`、`attachments/originals/`、`attachments/derived/`、`models/`、`backups/`和`exports/`相互分区并全部忽略Git。
- 备份：规划为每日生成本地备份并保留30天，并支持手动完整导出、校验和恢复演练；自动备份、导出和恢复均尚未实现。

## 安全与隐私

- 单一本地管理员账户，无公开注册。
- 私有组网设备边界加应用会话保护；不得仅依赖“知道地址”作为鉴权。
- 私有网络部署后使用Tailscale Serve私有HTTPS，不启用Funnel等公网暴露能力；当前该部署尚未实施。
- 云端AI适配器默认关闭；当前录入界面可选择自动、仅AI或仅本地规则，并显示实际模型与回退原因。独立的供应商/数据类型隐私提示仍需在后续设置或视觉/OCR接入任务中补齐。
- 日志不记录完整原始票据、密钥、访问令牌或不必要的个人信息。
- 配置和导出中的密钥不得进入普通Markdown、日志或备份清单明文区。

## 可靠性约束

- 正式记录、候选确认和关系创建必须具备事务性。
- 金额使用精确表示，不能用二进制浮点数保存货币。
- 公共发生时间保存可空`YYYY-MM-DD`及原文，不用默认日或分钟伪装精度；系统时间仍统一使用UTC。
- SQLite日期时间通过统一类型写为无偏移UTC、读为aware UTC；API返回带时区ISO 8601，前端显式按Asia/Shanghai展示。
- 尺寸记录对象、方向、是否近似及语义角色，已知数值统一保存为毫米，宽度、高度、长度均可为空表示未知。
- 同一来源可有多次提取运行；重新提取会使旧活动候选包失效，候选确认按来源版本和候选包版本防止陈旧写入。未来图片/OCR任务重试也必须保持幂等。

## 不允许随意改动的边界

- 原始来源不可被AI结果覆盖；用户纠错必须显式操作、递增版本、保留审计并标记关联正式记录待复核。
- AI候选与用户确认事实必须可区分。
- 多视图不得拥有独立事实副本。
- `ledger_kind`只允许`payment`、`refund`和`income`；金额统一使用`amount_minor`，类型、方向与完成状态必须一致。
- 正式接口、领域状态和破坏性数据变化必须先更新契约与决策记录。
