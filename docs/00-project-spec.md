# HomeBuild Log 项目规格

## 产品定位

HomeBuild Log 是面向个人业主的装修事件与知识管理系统。用户只需用自然语言、图片或票据描述“发生了什么”，系统保留原始输入，提取候选信息，并在用户确认后形成可关联的结构化记录。

系统不要求用户预先判断应该记到账本、问题还是决策。一条原始描述可以同时生成多种记录，并在时间线、账本、问题看板和空间档案中同步呈现。待办、普通问题和施工问题统一保存为“问题”。

## 项目目标

- 将聊天、相册、票据、现场观察和记忆中的装修事实整理为可检索、可追溯的个人档案。
- 降低记录门槛，避免用户在多个工具和表格之间重复录入。
- 保留事情发生、决策形成、问题处理、费用支付和知识调研的完整上下文。
- 让同一事实按时间、空间、费用、问题、材料和行动项等视角复用。
- 通过真实装修事件持续验证业务分类和字段，而不是先按想象固化数据库。

## 目标用户与使用边界

- 首版用户：单一业主本人，个人私用。
- 首版项目：界面只突出一个活跃装修项目；领域模型保留项目根实体，方便未来归档或扩展。
- 使用设备：Windows电脑为本地服务主机，电脑端响应式Web已实现，手机通过响应式Web/PWA访问（尚未实现）。
- 协作边界：首版不向家庭成员、工人或设计师开放账户；人员和商家只作为装修记录中的参与对象。

## 产品原则

1. **原始事实优先**：原始文字、图片和票据不可被AI结果静默覆盖；用户显式修改来源必须递增版本、保留审计、使旧候选失效，并提示关联正式记录复核。
2. **人在回路**：本地规则或AI只生成候选记录；金额、施工质量和关键决策必须经用户确认。
3. **一事多记录**：一次描述可生成零条、一条或多条关联记录，不强制单一分类。
4. **视图不是副本**：时间线、账本、看板和空间档案读取同一底层记录，不复制业务事实。
5. **不确定性显式化**：未知、推算、近似、待补充和用户已确认必须可区分。
6. **本地与隐私优先**：默认本地保存数据和附件；云端AI必须显式配置，不允许静默上传。

## 首版业务记录

| 类型 | 用途 | 典型内容 |
| --- | --- | --- |
| 事件 | 装修时间主线及阶段事实 | 现场查看、施工开始、施工完成、沟通、验收测试 |
| 账目 | 每笔实际资金流 | 付款、预付款、退款与收入 |
| 问题 | 所有需要继续处理或跟踪的事项 | 缺陷、争议、到货验收、补资料、现场规划、问题复核 |
| 尺寸 | 可复用的数值与测量语义 | 材料规格、现场测量、设计要求、近似尺寸 |
| 决策 | 已确认或待确认的方案选择 | 铺贴方式、材料选择、空间改造 |
| 调研 | 问题、选项、证据与结论 | 器材比较、材料选型、施工知识学习 |

施工进度、里程碑和验收测试先作为事件子类型；材料作为共享档案；空间拆改由事件、决策和空间关联共同表达。

## 核心场景

### 随手交代一件事

用户输入文字或附件，系统保存原始来源，识别可能的时间、空间、人物、金额、尺寸、问题、决策、采购和调研，随后展示可编辑候选记录。来源列表展示未分析、待处理候选数量、已生成记录数量或“已分析，无待处理”；“待处理”仅统计尚未确认且未被用户忽略的候选，不恢复待确认箱或稍后处理流程。

当前已实现可选云端AI文字提取：默认按MiMo、DeepSeek顺序尝试，供应商顺序可由本地配置覆盖；全部失败或未配置时由不联网的`local-rule-v1`提供建议。所有引擎只产生持久化候选；前端默认勾选全部未确认候选，用户仍可检查证据与确定性、修改类型和字段、移除候选或追加同形手工记录。

### 确认候选记录

用户可调整 AI 自动补全的字段、修改记录类型、追加手工记录并确认所选候选。确认操作一次性创建多条正式记录及其关联，原始来源始终独立保留。

### 查清某段装修历史

用户可按发生日期、阶段、空间、记录类型、商家或关键词检索，查看某件事情的原始描述、附件、后续决策、费用和处理结果。

### 追踪问题

问题看板统一展示原待办、普通问题和施工问题，使用待处理、处理中、已完成三种状态。完成时自动登记实际完成日期，并保存实际处理结果。

### 管理费用与采购

账目以子类型区分付款、退款和收入，只保存真实发生或明确计划的资金流水。金额统一保存为正数并由方向表达语义；净支出统一按付款减退款再减收入计算。

## 功能范围与当前状态

### 当前已实现

- 文本、图片和票据来源录入，保留原始内容、精确录入时间与附件元数据；支持可审计修改和带影响预览的安全级联删除。
- 六类记录的手工创建、编辑、查看、归档和关联。
- 文本AI候选提取、自动补全、即时预览、人工调整、手工追加和确认。
- 时间线、账本、问题看板、空间档案、基础搜索和统一记录详情。
- 默认中文概览、核心视图图表、六类记录分析和安全 AI 运行分析；图表可进入同口径真实明细。
- 账目与采购统一使用人民币，不提供多币种录入、换算或分组。
- 房屋—房间—局部构件的空间层级。
- 关键词和结构化条件检索。
- 单一本地管理员账户和JWT Bearer Token认证；当前通过Windows本地服务访问，不提供公网注册。

### 已批准但尚未实现
- 阶段4图片与票据OCR/视觉识别、持久化后台任务、PWA安装、离线草稿、同步去重和Tailscale Serve私有HTTPS。
- 阶段5搜索优化、重复检测、批量导入、完整导出、恢复验证、每日本地备份和隐私审计。
- 调研/采购/决策独立列表、设置页、家庭协作和交互户型图均需后续任务另行授权。

## 非目标

- 首版不做施工项目管理ERP、专业会计、合同法律归档或工程质量鉴定。
- 首版不提供家庭、工人、设计师多账户协作和细粒度权限。
- 首版不做交互式户型图、BIM、三维空间、自动算料或自动报价。
- 首版不让AI绕过用户确认直接写入正式账目、问题或决策。
- 阶段1“不创建八类业务表、不实现AI”的限制只描述当时的历史边界；阶段2与阶段3A现已完成。OCR、PWA和自动备份仍未实现。

## 质量与安全要求

- 可追溯：正式字段能够定位到原始来源或用户补充确认。
- 一致性：多视图展示同一记录，状态变化在所有视图一致。
- 可恢复：阶段5完成后，数据库、附件和配置应可整体导出，恢复流程必须经过实际演练；当前导出、自动备份和恢复验证尚未实现。
- 隐私：附件、地址、联系方式和票据默认不离开本地；外部AI调用可见、可关闭。
- 中文优先：支持中文自然语言、中文OCR、人民币、厘米等常用装修表达和Asia/Shanghai时间语义。
- 失败可见：识别失败、低确定性、冲突、重复和缺字段不得伪装成成功。
- 时间一致：系统时间统一保存UTC并按Asia/Shanghai展示；业务发生时间保存可空日期，录入时间不能冒充事情发生日期。

## 首版验收场景

- 样本001可由一个来源形成选购事件、花色决策、采购、500元预付款账目和送货验收问题。
- 样本004可形成现场事件、主卧门口问题、不返工决策和等待门套遮挡复核问题。
- 样本007可形成水电施工事件、三项技术决策、补充资料问题和“打压通过”的验收事件，且不得把通过的测试误记为缺陷。
- `60*120cm`可标记为材料规格，`厨房门宽度约240cm`可标记为近似设计尺寸，两者不会混淆。
- 计划、已发生事实、AI推断、算术推算和用户确认状态可分别展示。
- 修改候选分析不会改变原始描述，任何正式记录均可回溯到来源。

## 后续验证项

- AI调用成本上限、OCR方案和本地模型硬件要求；文本供应商当前默认采用MiMo优先、DeepSeek后备并保留配置切换。
- 附件大小、文件类型、保留期限和缩略图策略。
- 搜索实现、重复记录判定和批量导入格式。
- 未来家庭协作、远程分享、提醒通知和交互户型图的优先级。
